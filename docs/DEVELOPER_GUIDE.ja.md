# 開発者向けガイド

[English version](DEVELOPER_GUIDE.md)

## フォルダ構成

- app/index.html：試作品の画面構造。
- app/styles.css：スマホ対応のデザイン。
- app/src/logic.js：テストしやすいデータ処理と提案ロジック。
- app/src/main.js：画面表示、フォーム、ブラウザ内データ保存。
- app/tests/logic.test.js：Node.jsによる単体テスト。
- docs/CURRENT_STATUS.ja.md：実装済み・未実装の状況。
- docs/BUILD_PLAN.ja.md：開発タスクと作業ID。
- .github/workflows/ci.yml：プルリクエストの自動検査。
- .github/pull_request_template.md：レビュー時の確認項目。

## 開発を始める方法

必要な環境はPython 3とNode.js 20以上です。現在の試作品に追加のnpmパッケージは必要ありません。

1. リポジトリをフォークまたはクローンします。
2. リポジトリのルートで npm run check を実行します。
3. python3 -m http.server 4173 を実行します。
4. http://localhost:4173/app/ を開きます。
5. チャットとボードを試します。ただし別のブラウザとのデータ共有は未実装です。

ブラウザの制限により、ローカルファイルを直接開くとJavaScriptモジュールが読み込まれないことがあります。必ずローカルサーバーから確認してください。

## 共同開発のルール

1. 一つの作業ごとにブランチかフォークを作り、原則としてメインブランチを直接書き換えません。
2. 大きな作業の前にGitHub Issueと完成条件を決めます。
3. データ処理と画面表示のコードは可能な限り分けます。
4. ユーザーの入力内容を画面に表示するときは、安全なテキスト表示方法を利用します。
5. APIキーやパスワードを公開コードに書きません。
6. 将来の認証とグループ権限は必ずサーバー側で確認します。
7. 新しい機能にはテストを追加し、プルリクエストの自動検査を確認します。
8. 完成した機能と未完成の機能を開発状況ページに正確に反映します。
9. レビューを受け、複数の人が作った機能を一つのシステムとして統合します。

## 将来のシステム構成

ブラウザ画面 → 認証API → グループ・チャットサービス → データベース・リアルタイム配信 → 共有ボードとイベント管理。

AIを導入するときはサーバー側の接続部分を独立させ、適切な同意を得た会話だけを利用します。提案は人が承認するまで下書きとして扱います。

公開リポジトリのライセンスはまだ決まっていません。大きなコードを提供する前に、成果物の扱いとライセンスについて管理者と確認してください。

## 個人情報と安全性

公開Issueやプルリクエストに、実際の個人情報、会話履歴、連絡先、APIキーを掲載しないでください。テストには架空データか許可されたデータを使います。
