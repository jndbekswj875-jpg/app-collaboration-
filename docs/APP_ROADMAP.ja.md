# コミュニティAIワークスペース — チャットを先に作り、その後にAIでイベント運営をサポート

[English version](APP_ROADMAP.md) · [プロジェクト概要](../README.ja.md) · [現在の開発状況](CURRENT_STATUS.ja.md)

## 目指すサービス

友人との集まり、個人イベント、地域コミュニティなどで使える、**無料利用を目指したチャット型ワークスペース**を作ります。まずグループ内の会話と情報共有を便利にし、その後で**AIイベント主催者アシスタント**を追加して、繰り返し発生する事務作業の負担を減らしたいと考えています。

**最初からAIだけを作るのではありません。** グループの会話、共有情報、参加権限が整っていなければ、AIを追加しても全員が同じ予定を理解できるようにはなりません。

## 準備段階 — 実際の困りごとを知る

最近のイベントを振り返り、何が伝わらなかったか、誰が同じ説明を繰り返したか、どんな変更が見落とされたか、普段どのアプリを使っているかを聞きます。非公開の会話を無断で収集せず、公開してよい一般的な内容だけを集めます。

**目標：** 実際に繰り返し起きている課題を理解し、チャットと共有ボードの最小構成を決めます。

## 第1段階 — チャット型ワークスペースを完成させる

**目標：** AIを利用しなくても、一つのイベントをグループで企画できること。

| 機能 | できるようにしたいこと | 実装順 |
| --- | --- | --- |
| アカウントと非公開グループ | ログイン、招待、参加権限の管理 | 最初 |
| リアルタイムチャット | 別々の端末で会話を共有し、更新後も履歴が残る | 最初 |
| イベントの情報ページ | 日時、場所、説明、変更内容を一か所にまとめる | 最初 |
| 共有ボード | タスク、確定事項、未解決の質問を手動で追加・修正する | 最初 |
| 出欠確認 | 参加・未定・不参加を回答し、変更できる | チャットの後 |
| お知らせ | 重要な変更を確認し、通知を受ける条件を選べる | 安全な共有機能の後 |
| スマホ対応 | 日本語・英語で使いやすく操作できる | 最初 |

### 最初の完成条件

招待された2人が別々の端末からログインし、**同じチャット履歴と共有ボード**を確認できます。主催者が予定を更新すると、参加者は最新の確定情報を見つけられます。グループ外の人はアクセスできません。AIを使わなくても基本的なイベント企画ができます。

### 利用例

1. 「土曜日のピクニック」というグループを作ります。
2. 友人を招待し、時間や集合場所について話します。
3. 候補日を共有ボードに書きます。
4. 全員の合意を確認してから日時を確定します。
5. 飲み物の担当者を本人の了解を得て決めます。
6. 予定と準備状況を一か所で確認します。

**現在の状態：** v0.1は一つのブラウザ内でだけ動く試作品です。安全なログイン、複数人のリアルタイム同期、サーバーへの保存はまだ実装されていません。

## 第2段階 — AIイベント主催者アシスタントを追加する

**目標：** チャットや共有情報が使えるようになった後、主催者が繰り返す作業をAIが手伝います。

| 繰り返す作業 | AIに手伝ってほしいこと | 人の確認 |
| --- | --- | --- |
| 見逃した会話を読み直す | 指定した会話の要点や変更をまとめる | 対象を利用者が選ぶ |
| 同じ質問に何度も答える | 確定した情報から回答の下書きを作る | 公開前に確認 |
| 準備リストを作る | 相談内容に基づくタスク候補を整理する | 追加前に承認 |
| 不足している情報を探す | 未回答の質問や決まっていないことを示す | 確定前に確認 |
| 出欠の未回答を確認する | 権限の範囲で未回答者を見つける | 連絡する前に承認 |
| リマインダーを書く | 案内やお知らせの下書きを作る | 送信前に承認 |
| 次の行動を決める | 優先して確認すべき作業を提案する | 主催者が選ぶ |
| 日英の情報共有 | 必要に応じて説明や文章の翻訳案を作る | 利用者が内容を確認 |

### チャットボットとの会話例

> **主催者：** 「土曜日のイベントで、あと何をすればいい？」
>
> **AI：** 「集合場所が未確定です。出欠の未回答が2人いて、飲み物の担当も確認が必要です。案内文の下書きを作りますか？」
>
> **主催者：** 「集合場所と出欠を確認するメッセージを考えて。」
>
> **AI：** 送信する前に確認できる**下書き**を作ります。勝手には送信しません。

AIが確定事項を捏造する、無断でタスクを確定する、許可なく連絡する、個人情報を公開する、予約や支払いを行うことは想定していません。

### AIを追加する開発手順

1. グループ、メッセージ、イベント情報、確定したタスクのデータ形式を整えます。
2. 利用者が明示的にAIへ相談でき、対象範囲と同意を確認できるようにします。
3. 最初は既存のAIモデルを、安全なサーバー経由のAPIで接続して検証します。
4. 必要最小限の許可された情報から、要約、参照先、タスク候補、不明点を構造化して出力します。
5. AIの結果は**承認待ちの下書き**として保存します。
6. 人が修正、承認、却下できるようにします。
7. 架空または使用許可を得た日本語・英語のイベント会話で、正確さ、間違い、作業時間、費用を測ります。
8. 実際の需要が増えた場合、自前モデルや専門的に調整したアシスタントとの比較を考えます。

**独自AIを作ること**は、既存モデルの周りにイベント運営用の機能や指示を組み合わせて改善することから始められます。最初から巨大なAIをゼロから学習する必要はありません。専用の学習済みモデルは現在存在しません。

## 大切な原則

- **グループのプライバシー：** サーバー側ですべての閲覧・変更権限を確認します。
- **AIへの明確な同意：** 会話を許可なく裏側でAIに送信しません。
- **提案と確定を区別：** 「土曜日はどう？」を「土曜日に確定」と誤認しません。
- **最終判断は人：** 連絡・招待・リマインダーは権限のある利用者の承認が必要です。
- **最小限のデータ利用：** 必要な会話のみ扱い、削除・保存期間・連絡先の非公開設定を考えます。
- **無料利用を目指す：** 個人やコミュニティ向けに無料で使えることを目標にしています。現在はまだ本番サービスではありません。
