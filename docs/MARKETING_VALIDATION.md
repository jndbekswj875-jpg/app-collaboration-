# Marketing, website growth & business validation / 集客・Webサイト・ビジネス検証

**Purpose / 目的:** Connect the Community AI Workspace concept to real audience needs, the owner's existing website, and a measurable marketing/business experiment—without claiming a monetized website or a proven product.

**目的:** コミュニティAIワークスペースのアイデアを、既存Webサイト、ユーザーの実際の課題、マーケティング活動とつなげて検証します。広告収入やプロダクト価値が確立したと誤解させないようにします。

## 1. Two separate business loops / 収益化までの2つのルート

### A. Website and content / 既存サイトの成長
**English**
1. Publish an accurate, original project story or practical event-planning article relevant to an identifiable audience.
2. Help visitors find a useful answer; add clear navigation to a **feedback or interest page**.
3. Invite voluntary feedback and consent-based pilot participation; measure qualified visits and next-step engagement.
4. Improve content based on actual reader questions, technical accessibility, and search performance.
5. **AdSense is separate**: verify site policy compliance and approval before treating ads as a business revenue source. AdSense eligibility, original content and quality must not be confused with simply having more visits.

**日本語**
1. 誰のどんな課題を解決するのか明確にし、独自性のある役立つ記事や開発ストーリーを公開します。
2. 訪問者に必要な情報を提供し、興味がある人だけが進めるアンケート・参加希望の導線を設けます。
3. 実際の閲覧・問い合わせ・試用希望を計測し、反応をもとにコンテンツを改善します。
4. Google検索の表示・クリック・回遊を確認し、実際の読者の疑問に答える記事へ磨きます。
5. **AdSenseは別の審査が必要**です。訪問者が増えただけで承認や収益が保証されるわけではありません。

### B. Product and service / アプリの事業化
**English**
1. Observe one real group using chat to plan an event.
2. Identify what coordination action is repeated or forgotten.
3. Test minimal chat + shared board, then an optional permissioned AI draft.
4. Measure actual minutes saved, clarity, mistakes, member return, and organizer repeat use.
5. Only if people repeatedly use or commit, test a paid organizer service or subscription with transparent cost.

**日本語**
1. 実際のグループがイベントを相談する様子を観察します。
2. どの連絡・確認・整理作業が繰り返されているかを確認します。
3. 最小のチャット＋共有ボードを試し、必要に応じてAIによる下書き整理を導入します。
4. 主催者が節約できた時間、連絡ミス、再利用や満足度を実測します。
5. 継続的な利用や有料契約への具体的な意思を確認してから、サブスクリプション等を検討します。

```text
Useful owned-site article / 役立つ記事
       ↓
Interest / qualified visitor / 関心のある読者
       ↓
Voluntary feedback / 自発的なフィードバック
       ↓
Real-event pilot / 実際のイベントで試す
       ↓
Measured problem solved / 効果の実測
       ↓
Repeat use or paid commitment / 継続利用・支払い意思
       ↓
Possible paid service / サービス化を判断
```

## 2. Website placement / 既存サイト内の配置

**English:** A small Ideas/Projects/Experiments page on an existing owned domain may be sufficient to explain the concept and link to GitHub. Do **not** replace the site's current audience-focused content (for example, its existing English-learning or travel pages) with an unrelated chat-app sales pitch. Only add a major navigation section or community signup if evidence shows that site's visitors genuinely want it. The future working product may live at an appropriate route or subdomain, with private pages correctly excluded from indexing and with separate policy/security review.

**日本語:** 最初は既存の自社ドメインの「Ideas」「Projects」「Experiments」などのページで構想を紹介し、GitHubへリンクする方法が考えられます。既存の英語学習や旅行などのコンテンツを、関係の薄いアプリの宣伝に置き換えません。利用者の関心が確認されてから、専用メニューやサブドメインを判断します。非公開チャットを検索公開することはありません。

## 3. Content experiments / 発信するコンテンツ案

The first article should be **useful even if the software never launches**. / アプリがなくても役立つ内容を最初に発信します。

- **Example 1:** “How to organize a small BBQ without losing decisions in group chat” / 「グループチャットで決定事項が埋もれないBBQ企画の方法」
- **Example 2:** “An event organizer checklist for RSVP, tasks, and contributions” / 「イベント主催者の出欠・役割分担・会費管理チェックリスト」
- **Example 3:** “We tested AI chat summaries: what it organized correctly and incorrectly” — publish only after a real test, with anonymized permissioned examples. / 「AIによるイベント会話の整理を試した結果」※実際に検証した後のみ公開

Be transparent about what is researched, designed, prototyped, and actually deployed. / 調査・試作・本番公開を区別します。

## 4. Measurement map / 指標の整理

| Layer / 段階 | Suggested evidence / 指標 | What it does **not** prove / 誤解しないこと |
|---|---|---|
| Discovery / 認知 | GSC impressions, organic clicks, referring sources / 検索表示・クリック | Not AdSense approval or qualified users / 承認や需要の証明ではない |
| Website engagement / 閲覧 | Relevant landing visits, article navigation, interest form completion / 閲覧・問い合わせ | Not an actual customer payment / 売上ではない |
| Pilot use / 試用 | Opted-in testers, real chats, board updates, RSVP submissions / 試用参加 | Not repeat demand until repeated / 継続需要ではない |
| Useful AI / AIの価値 | Correct suggestions approved, review time, mistakes, cost per useful summary / 承認率・修正時間・費用 | Not automatic reliable decision making / 自動意思決定の正当化ではない |
| Product value / 価値検証 | Organizer minutes saved, repeat event usage, willingness to commit / 削減時間・継続利用 | Interest alone isn't revenue / 興味だけでは売上ではない |
| Revenue / 収益 | Verified paid fees or separately verified legitimate AdSense earnings and payout / 実入金・広告実収益 | Page views aren't payout / PVは入金ではない |

**Sample experiment / 初回テスト:** Find one organizer with an upcoming small event; record their current communication workflow; test whether a shared chat/task board removes one repeated manual step. If it doesn't, ask why before expanding features. / 実際の主催者一人から現状を聞き、共有ボードが一つの反復作業を減らすか試します。効果がなければ機能追加の前に原因を聞きます。

## 5. Important AdSense boundary / AdSenseについて

The existing website's Google AdSense status must be verified separately in the owner's account. A project case study, a feedback form, and a private AI chat app serve different user needs; **do not add thin or unrelated pages solely to chase search traffic or ad impressions**. For sustainable discovery, prioritize original, helpful content, clear site purpose, good mobile usability, working navigation and policy compliance.

既存サイトのAdSense審査状況は、所有者のアカウントで別途確認します。企画書・フォーム・非公開チャットを増やすこと自体が広告審査への近道ではありません。検索対策より先に、実際の人に役立つ独自コンテンツ、サイトの目的の明確さ、スマホでの操作性、安全性を優先します。

**Official resources / 公式資料:**
- [AdSense eligibility](https://support.google.com/adsense/answer/9724?hl=en)
- [Google Search Essentials](https://developers.google.com/search/docs/essentials)
- [Creating helpful, people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

## 6. Work and priority integration / 作業計画との連携

**English:** The public repo is an **idea and volunteer task map**, not a second personal daily planner. When the owner allocates actual development time, one scoped, measurable task should be selected from [BUILD_PLAN.md](BUILD_PLAN.md) and routed through the **existing dated Daily Plan and marketing/business task owner**. Keep website growth actions under the existing website marketing workflow; customer/product evidence under the existing business-plan owner. Avoid duplicating databases or treating discussions as completed development.

**日本語:** このGitHubは**アイデアと共同作業候補の一覧**であり、個人の毎日のToDoを増やすためのものではありません。実際に開発時間を確保したときだけ、[開発タスク](BUILD_PLAN.md)から一件を選び、既存のDaily Planとビジネス管理に連携します。サイトの集客は既存のWebマーケティング計画、アプリの価値検証は既存の事業計画で扱い、管理場所を増やしません。
