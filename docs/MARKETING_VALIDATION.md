# Learning from people who organize events

[Japanese version](MARKETING_VALIDATION.ja.md) · [Project overview](../README.md)

The Community AI Workspace is intended to be **free for personal and community use**. This document focuses on listening to potential users and testing whether a chat-based shared workspace actually helps. It is not a pricing plan or an invitation to hire developers.

## Event promotion is part of the workspace itself

This application can be an **event promotion and attendee communication hub**, not simply a private planning tool. The central use case is for an organizer to create an event, share its link, welcome interested people, communicate directly with attendees, and deliver changes in one controlled place.

**Visitor / attendee journey:** See event title and description → understand time, place and participation rules → choose to RSVP or request an invitation → ask a question → follow confirmed announcements → attend the event → optionally give feedback afterward.

**Organizer journey:** Create the event → share a link through appropriate existing channels → see interest and RSVPs → answer participant questions → publish one verified update → coordinate preparation in the same workspace → review feedback.

Public event information should remain separate from private attendee chat. An app cannot guarantee marketing reach merely by centralizing tools: organizers still need an audience and a way to share their event link. Automatic posting, emails, calls and advertising across third-party platforms are not supported now.

### What to learn from real users

- How many different apps or channels were required to organize the last event?
- Where did interested people first discover it?
- How often did organizers repeat the same answer or resend changes?
- Did people fail to notice a schedule, location or meeting-point update?
- Would one shareable event page plus direct chat make communication easier?
- Which reminders should be optional or require explicit approval?

**Potential evidence:** repeated-tool-switching reduced, fewer duplicate questions, clearer RSVP status, timely understanding of updates, more successful check-ins and organizer willingness to run another event. These are hypotheses to test, not measured results.

## Free communities, ticketed events, and AI-assisted promotion

The marketing tool has **two complementary uses**:

1. A host shares an accurate public event page and communicates directly with interested visitors and authorized attendees. This supports free community gatherings without requiring any ticket purchase.
2. If a host chooses a **paid event**, the same event page can later offer ticket types and secure purchase flow. Track *actual* verified purchases separately from page visits, RSVPs and expressions of interest.

**Potential funnel:** Event link viewed → relevant visitor understands the event → inquiry or RSVP → optional checkout → verified paid ticket issued → check-in → attendee feedback. Count unique paid orders and valid issued tickets; do not equate curiosity or unpaid reservations with revenue.

**AI marketing assistant goal:** Help write promotion copy from verified facts, draft event FAQs, prepare updates for human approval, and explain aggregated opt-in engagement. Don't perform unsolicited bulk outreach or personally target attendees based on private chats or transaction histories.

**Economic boundary:** Basic community use is intended to be free. Ticket prices belong to the hosted event. Provider fees, any future platform fee, payouts, refunds and taxes require separate review and transparent disclosure. None are currently live or established.

## What we want to learn

1. **Who experiences the information gap?** Friends, clubs, local organizers, study groups, sports groups, families or volunteers.
2. **Where does the information get lost?** Fast-moving chats, separate RSVP lists, changed details, missed reminders or unclear responsibilities.
3. **What makes the problem painful?** Repeated messages, forgotten decisions, organizer stress, late arrivals or people feeling left out.
4. **What could help?** A group chat, one shared board, event status, catch-up summary or user-controlled AI assistant.
5. **What feels simple and safe?** Invites, permissions, privacy, mobile access and reliable summaries.

## How to test the idea

- Ask people to describe **one real event** and one difficult moment in organizing it.
- Group similar feedback without collecting private chat histories.
- Show the prototype and make clear that it is single-browser only.
- Ask users which feature solves an actual problem, not just which features sound interesting.
- When secure multi-person chat exists, conduct an opt-in small-group test.
- Measure whether people miss fewer updates, save time, understand decisions, and choose to use the free tool again.

## Signs of useful progress

| Step | What we can measure |
| --- | --- |
| Discovery | Relevant people reading the project and sharing a specific problem |
| Feedback | Repeated, concrete problems across different kinds of events |
| Prototype | People can understand and use the core interface |
| Pilot | Actual organizers use the shared workspace for a real activity |
| Value | Fewer repeated explanations, faster catch-up, fewer missed decisions |
| Continued use | People choose to return for another event |
| Trust | Clear consent, corrections, and no accidental sharing of private information |

Do not invent participant counts or report sample demo messages as real feedback.
