# コミュニティAIワークスペース — 製品全体の設計図

[English version](PRODUCT_BLUEPRINT.md) · [プロジェクト概要](../README.ja.md) · [開発ロードマップ](APP_ROADMAP.ja.md)

**目指すもの：** 参加者同士の会話を中心に、イベントの作成・告知・意見交換・最新情報の共有・出欠管理・チケット販売まで、一つの場所で進められるサービスです。その後、AIイベント主催者・マーケティングアシスタントが繰り返しの運営業務を減らします。

**これは製品の構想であり、実装済み機能の一覧ではありません。** 現在はブラウザ内だけの試作品があり、本物の複数人チャット、決済、チケット販売、AI連携はまだ公開されていません。

## 1. 解決したい問題

イベントを開催するとき、告知用のSNS、招待メール、参加者用のチャット、出欠表、チケット販売サイト、変更を伝える連絡手段などを使い分ける場合があります。情報が分かれ、主催者の確認作業が増え、参加者は最新の内容を探しにくくなります。

**目標：** イベントそのものを情報共有の中心にします。チャットで相談し、確定事項は共有ボードとイベントページにまとめ、主催者が変更を一度公開すれば参加者が確認できるようにします。

## 2. 想定する利用者

- **コミュニティ主催者：** 最初は友人同士の無料イベント、地域の集まり、サークル、ボランティア活動など。
- **参加者：** イベントリンクから情報を確認し、質問、意見交換、出欠、必要ならチケットの購入を行う。
- **イベント運営者：** イベントの告知、準備、質問対応、入場管理、必要に応じたチケット販売をまとめる。

## 3. 一つのイベントでできるようにしたいこと

| 段階 | 主催者 | 参加者 |
| --- | --- | --- |
| 作成 | タイトル、説明、日時、場所、公開範囲、定員を設定 | 内容を確認 |
| 告知 | 一つのイベントリンクを共有 | イベントを見つける |
| 会話 | チャット・質問対応で意見を集める | 質問や意見を伝える |
| 準備 | 確定事項、担当、チェックリストを管理 | 最新の予定を見る |
| 参加 | 無料出欠または有料チケットを設定 | 出欠回答・必要なら安全に購入 |
| 変更 | 最新情報とお知らせを公開 | 集合場所や時間の変更を確認 |
| 当日 | チケット・参加状況を確認し入場対応 | 必要な入場情報を表示 |
| 振り返り | 集計とフィードバックを確認 | 次のイベントへの意見を伝える |

一般公開の告知内容と、参加者の非公開チャット・連絡先・購入情報は分離します。

## 4. 機能の構成

### A. チャット型ワークスペース — 最優先

まず非公開グループを作り、複数人がリアルタイムで会話し、履歴を保存できるようにします。決定事項、未回答の質問、タスク、イベントの基本情報を手動で共有します。**AIがなくてもイベントを運営できること**が第一条件です。

**最初の完成条件：** 招待された2人が別々のブラウザでログインし、同じチャットと共有ボードを安全に利用できる。部外者には閲覧・変更できない。

### B. イベント作成・告知・参加者との直接連絡

主催者がタイトル、イベントの紹介文、日時、場所、参加方法、更新情報を含むページを作ります。必要な人にリンクを共有し、参加希望者の質問や参加者との会話を同じ場所で管理します。

**集客の考え方：** このページはイベントを紹介するための中心になりますが、作っただけで自動的に人が集まるわけではありません。外部SNSや広告への自動投稿は現時点で実装されていません。

### C. 無料イベントと有料チケット販売 — 今後の機能

主催者はイベントに応じて、**無料出欠確認**、**無料チケット**、**有料チケット**などを選べるようにしたいです。

1. チケットの種類、数量、販売期間、価格、通貨を登録する。
2. 購入する人が、確定前に価格と必要な追加料金を確認できる。
3. アプリから**信頼できる決済事業者**を利用して安全に支払う。
4. サーバーで決済結果と注文の状態を確実に検証し、二重発行や売り過ぎを防ぐ。
5. 確認された注文に対して、固有のチケットや入場コードを発行する。
6. 参加者が同じワークスペースでチケットと最新情報を確認できる。
7. 会場で安全に受付・入場確認を行う。
8. キャンセル、払い戻し、譲渡、購入者対応などの規則を明示する。

**必要な安全性：** チケット在庫・同時購入の管理、二重決済の防止、決済通知の検証、不正購入・チャージバック対策、返金、本人確認や売上の振込条件、税金・手数料・利用規約などです。カード番号をアプリ自身で保存しません。決済事業者や料金体系はまだ決めていません。

**基本サービスの無料利用と、有料イベントのチケット代金は別です。** 誰でも利用できる無料のコミュニティ機能を目指しながら、主催者が有料イベントを開催できるようにする構想です。将来の決済手数料・サービス利用条件は、実際の販売開始前に明示する必要があります。

### D. AIイベント主催者アシスタント — チャットの完成後

例えば次のような質問に答える仕組みを考えています。

- 「昨日から何が決まった？」
- 「土曜日のイベントで、まだ準備が必要なことは？」
- 「誰が持ち物を担当する予定？」
- 「確定した情報からチェックリストを作って」
- 「出欠の未回答者に送る案内文を下書きして」

AIの結果は**人が確認する下書き**です。未確定の予定を勝手に確定したり、権限のない情報を読んだり、許可なく連絡したりしません。

### E. AIマーケティングアシスタント — イベント情報が整った後

主催者の集客・案内作業も手伝えるようにします。

- イベント名や説明文、告知文の案を作る。
- 日本語・英語で紹介文やお知らせの下書きを作る。
- 確定済みの情報に基づき、参加者のよくある質問への回答案を作る。
- 主催者が指定した対象や目的に応じて、告知内容や時期の案を出す。
- 同意した参加者に対する案内文・フォローアップの下書きを用意する。
- 実装・許可された範囲で、ページ閲覧、出欠、チケット販売数などの**集計データ**を説明する。

**AIマーケティングエージェントは、勝手に広告を配信する仕組みではありません。** 外部への投稿、連絡、広告の購入、価格変更、金銭の移動などには、権限と人の承認が必要です。許可のない個人情報の収集やプロファイリングは行いません。

## 5. AI開発の方針：既存モデルから始め、将来は自前モデルを評価

**最初：** OpenAI APIまたはAnthropic Claude APIなど、既存の開発者向けAIモデルを安全なサーバーから利用します。ChatGPTやClaudeの一般向け月額サービスとは別のAPIです。イベント情報の読み取り、ツール、指示文、下書きの形式、同意や承認の仕組みを開発します。

**検証：** 日本語・英語で正確に要約できるか、誤った決定を作らないか、修正時間、応答速度、APIの使用量・費用を測ります。

**長期目標：** 許可されたオープンウェイトモデルを自前サーバーで実行する方式や、必要に応じてモデルを追加学習する方式を比較します。品質、GPU、電気代、サーバー、開発・保守費を含めた総費用で判断し、モデルを交換できる接続部分を設計します。

**注意：** 「自分たちのAIを作る」は最終的な開発目標であり、最初から巨大な基盤モデルをゼロから学習する必要はありません。現在、独自の学習済みAIモデルは存在しません。

## 6. 開発の順番

| 段階 | 開発するもの | 前提条件 |
| --- | --- | --- |
| M0 現在 | ブラウザ内だけの試作品と疑似的な提案機能 | リポジトリにコードあり。本番未公開 |
| M1 | 安全なグループチャット、認証、履歴保存、共有ボード | サーバー・データベース・権限 |
| M2 | イベントページ、告知リンク、質問対応、出欠、更新情報 | M1 |
| M3 | チケット種類、決済、発行、入場確認 | M2と決済事業者 |
| M4 | 既存AIモデルによる主催者・集客サポート | M1–M2、同意と承認の仕組み |
| M5 | 自前モデルの比較・評価 | M4の実測データ |

チケット販売とAIの実装は、基本的なデータと権限の仕組みが完成した後、**独立した機能として並行開発**することもできます。無料イベントでの利用を妨げない設計にします。

## 7. 現在できないこと

- 本物の複数人チャット、決済、チケット販売、本番のAIは未公開です。
- イベントを公開するだけで集客や売上が保証されるわけではありません。
- 電話、メール、外部広告・SNS、決済事業者をすべて置き換えたわけではありません。
- AIが勝手に人へ連絡したり、広告を購入したり、価格やお金を変更したりする仕組みではありません。
- 料金、返金、法令・規約への対応はチケット販売開始前に決める必要があります。
