# イベントの告知・参加者との連絡・運営を一つのワークスペースに

[English version](EVENT_HUB_CONCEPT.md) · [プロジェクト概要](../README.ja.md) · [開発ロードマップ](APP_ROADMAP.ja.md)

## 解決したい問題

イベントを開くとき、告知にはWebサイトやSNS、招待にはメール、相談には別のチャット、出欠には表、急な変更には電話やメッセージなど、さまざまなサービスを使うことがあります。情報が分かれてしまい、参加者が最新の予定を見逃す原因になります。

**作りたいもの：** イベントの紹介、招待、参加者との会話、確定したお知らせ、準備の管理を一つにまとめた、無料利用を目指すワークスペースです。

これは**将来のサービス構想**であり、イベントの告知・集客機能がすでに使えるという意味ではありません。

## イベントを開催するまでの流れ

| 段階 | 主催者ができるようにしたいこと | 参加者ができるようにしたいこと |
| --- | --- | --- |
| 1. 作成 | タイトル、説明、日時、場所、主催者、公開範囲を設定する | どんなイベントで誰が開催するか理解する |
| 2. 共有 | イベントを紹介するリンクを作って必要な人に届ける | 一つのリンクからイベントを確認する |
| 3. 招待 | 必要に応じて参加希望を受け付けたり、招待を送ったりする | 参加方法やルールを確認して回答する |
| 4. 会話 | イベント内で参加者からの質問に回答し、相談する | 他のアプリに移動せず、主催者に質問できる |
| 5. 準備 | 出欠、担当、チェックリスト、未決定事項を管理する | 確定した予定と自分の担当を確認する |
| 6. 更新 | 重要なお知らせや変更履歴を一か所で公開する | 最新の情報を確認し、希望に応じて通知を受ける |
| 7. 当日 | 最新の集合場所や時間を分かりやすく案内する | 当日に必要な情報を一か所で探せる |
| 8. 改善 | 参加者の意見や困りごとを振り返る | 次のイベントに向けて感想を伝えられる |

## このアプリを集客・告知の中心にもしたい

例えば地域の趣味の集まりでは、イベントページに目的、開催日時、場所、参加方法をまとめられます。興味のある人は同じページを見て、参加希望を伝えたり、質問したりできるようにしたいです。

イベントのリンクを、既存のWebサイト、SNS、コミュニティ、友人同士の連絡手段などで共有する方法が考えられます。ただし、**一つにまとめるだけで自動的に人が集まるわけではありません。** 誰にどのように知らせるかは、主催者が考える必要があります。

外部サービスへの広告出稿や自動投稿は現在の機能ではありません。必要性と許可・利用規約が確認できた場合の将来的な候補です。

## 直接の連絡とリアルタイムの最新情報

主催者用の画面には、次の情報をまとめたいと考えています。

- **イベント概要：** タイトル、日時、場所、状況、共有リンク。
- **参加者：** 招待状況、出欠、権限に応じて確認できる情報。
- **チャット・質問：** 主催者と参加者がイベント内でやり取りし、必要な場合は通報できる。
- **お知らせ：** 確定した変更、公開日時、過去の更新内容。
- **準備ボード：** チェックリスト、担当者、未解決の事項。
- **将来のAI：** よくある質問の回答案、変更内容の要約、リマインダーの下書き。

集合場所が変わったとき、主催者がイベントの情報を**一度更新すれば**、権限のある参加者が最新情報を確認できる仕組みを目指します。アプリ内通知やプッシュ通知は、本人の設定や許可に基づいて追加することを考えます。現時点では実装されていません。

**電話やメールを毎回使い分けなくてよい**ことが目標ですが、必要な緊急連絡方法までなくすわけではありません。アプリ内通話、メール・SMSの送信は、必要性が分かった場合に別途検討します。

## 一般公開する情報と非公開の会話を分ける

イベント紹介ページには、主催者が公開を認めた情報だけを表示します。参加者一覧、個人の連絡先、非公開チャット、招待用の情報、欠席理由などは適切に保護します。

公開範囲の例：
- **一般公開のイベント概要：** イベントの説明と公開してよい参加方法。非公開チャットは表示しない。
- **招待制イベント：** 招待を受け、権限が確認された人だけが詳細を閲覧できる。
- **参加者用ワークスペース：** チャット、出欠、担当、お知らせを参加権限に応じて表示する。

質問や投稿、参加には迷惑行為への対策、本人確認や招待の管理、通報や削除の機能が必要です。リンクを知っているだけで非公開会話を読める仕組みにしてはいけません。

## イベントページにチケット販売を追加する（今後の予定）

同じイベントのページで**無料の参加登録**または**有料チケット**を選べるようにしたいと考えています。参加者は別々のサービスを行き来せず、イベント情報と入場情報を確認できます。

- 主催者がチケットの種類、価格、通貨、枚数、販売期間を設定する。
- 参加者が購入前に販売状況と合計金額を確認する。
- 信頼できる決済事業者を使い、サーバー側で支払い結果や重複を確認する。
- 確認済み注文に対して固有のチケット・入場コードを発行し、同じイベント内で表示する。
- 受付で利用状況を確認し、返金・キャンセル・問合せには明示した規則で対応する。

**チケット販売は現在まだ実装されていません。** 在庫管理、安全な決済、返金、販売者の条件を先に整える必要があります。一般公開のイベント情報と個人の注文情報は別の権限で管理します。無料イベントには決済が必要ない設計を保ちます。

その後に、**AIイベント主催者・マーケティングアシスタント**が、確定情報に基づいて紹介文、質問への回答案、お知らせ、フォローアップの下書きを作ります。勝手に決済、価格変更、返金、連絡をしません。

## AIアシスタントは基本機能の後に追加する

安全なイベントページ、チャット、共有情報が動くようになった後、**AIイベント主催者アシスタント**に次の作業を手伝ってもらいたいです。

1. 参加者から繰り返し出る質問を整理し、よくある質問の下書きを作る。
2. **確定した日時や場所**に基づき、質問への回答案を作る。
3. 前回の確認から何が変更されたかを要約する。
4. 準備チェックリスト、未回答の出欠、未担当の作業などを示す。
5. お知らせやリマインダーの下書きを作り、人が承認してから連絡する。
6. 必要に応じて日本語・英語の情報共有を手伝う。

適切な同意なく非公開会話を読み込んだり、合意していないことを確定したり、勝手に一斉連絡や宣伝、予約、支払いをしたりしません。

## 開発する順番

**第1段階：** 安全なグループチャット、参加権限、イベント情報、手動の共有ボード。  
**第1段階の拡張：** イベント紹介ページ、参加者の質問、出欠、確定したお知らせ、任意の通知。  
**第2段階：** 同意に基づくAI要約、よくある質問、タスクの提案、人が承認する連絡の下書き。  
**将来の候補：** メール送信、通話、外部SNS投稿、カレンダー連携など。需要に応じて検討します。

詳しい開発内容は[開発タスク一覧](BUILD_PLAN.ja.md)にまとめています。

## 主催者や参加者の方に聞いてみたいこと

- イベントの告知や運営に、どのアプリを使っていますか？
- 参加者はどこでイベントを知りますか？
- 同じ質問に繰り返し答えたり、変更を何度も伝えたりしていますか？
- チャットやメールが分かれていて、重要な変更を見落としたことはありますか？
- 一つのイベントページでチャット、出欠、お知らせを確認できると便利ですか？
- どんな情報は非公開にしたいですか？どのような通知なら受け取りたいですか？

[日本語でアイデアを投稿する](https://github.com/jndbekswj875-jpg/app-collaboration-/issues/new?template=feedback-ja.yml)。GitHub Issueは公開されます。非公開の会話や個人情報は投稿しないでください。

**現在の状況：** リポジトリには一つのブラウザ内だけで動く試作品があります。一般公開のイベントページ、複数人のリアルタイムチャット、参加者への通知、本物のAI、外部への自動告知は未実装です。
