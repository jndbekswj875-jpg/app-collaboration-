# Webサイト集客とビジネス価値の検証

**英語版：** [English version](MARKETING_VALIDATION.md)

この資料は、役立つ記事から関心のある人と出会い、実際のイベントで試作品を検証し、その結果を将来のサービス化に生かすための公開向けアイデアです。**Webサイトの広告収入とアプリの有料サービス化は、別々の事業モデルです。**

## ユーザーの課題から役立つ記事を作る

まず、実際のイベント主催者が困っていることを一つ見つけます。例えば、グループチャットの中で決定事項が流れてしまう問題です。**アプリが完成していなくても読者の役に立つ**独自の記事を考えます。

記事の例：
- 「グループチャットで決定事項を見失わないイベント企画の方法」
- 「出欠確認・担当者・会費を管理するための主催者チェックリスト」
- 「イベント会話をAIに整理させて分かったこと」※実際に許可を得てテストした後に限る

既存Webサイトの「アイデア」「制作実績」などで紹介する方法もありますが、そのサイトに来る人に関係がある場合だけにします。未完成の機能を利用可能であるかのように宣伝しません。

## フィードバックと試用への案内

役立つ記事から、興味がある人だけがアイデアを確認したり、簡単な意見を送ったり、試用を希望したりできる導線を設けます。不要な個人情報を集めず、利用目的・公開範囲を示し、実際の会話を共有するときは許可と匿名化を徹底します。

```text
独自性のある役立つ記事
           ↓
関心のある読者
           ↓
自発的な意見・試用希望
           ↓
一つの実際のイベントで検証
           ↓
作業時間・正確さ・費用を実測
           ↓
継続利用・具体的な支払い意思を確認
           ↓
有料サービス化を判断
```

## 収益化のルートは分けて考える

**Webサイト広告：** 広告掲載には、サイトの品質や規約などの条件を満たし、必要な審査で承認されることが必要です。アクセスや検索流入が増えるだけで、承認や収益が保証されるわけではありません。非公開チャットは公開コンテンツの代わりにはなりません。

**将来のアプリ事業：** 実際のグループが繰り返し利用し、主催者の負担が軽くなるなどの価値が確認できた場合に、月額利用料などの可能性を検討します。試用の結果と実際の運用費が分かるまでは、料金や売上を決め打ちしません。

検索表示、PV、登録数、興味、支払い意思、実際の入金を同じ成果として扱わないことが重要です。

## 検証する指標

| 段階 | 計測すること |
| --- | --- |
| 認知 | 検索キーワード、表示数、クリック数、流入元 |
| サイトの利用 | 関連ページの閲覧、回遊、意味のある問い合わせ |
| 試用希望 | 実際に試したいと同意した主催者 |
| 実際の利用 | 招待者、チャット利用、出欠回答 |
| 主催者への価値 | 節約した時間、繰り返しの質問減少、共有ボードの有用性 |
| AIの品質 | 正しい提案、誤った決定、修正時間、応答速度 |
| AIの費用 | 実際の支出、イベント当たりの利用量、有用な結果1件の費用 |
| 継続利用 | 次回のイベントでも使いたいか、実際に再利用したか |
| 収益 | 確認できるサービス代金、または別途確認できる広告収入 |

## 最初の検証実験

実際に近々イベントを企画する主催者に話を聞き、現在の連絡方法や作業時間を記録します。適切な同意を得て、小さなチャット・共有ボードを使ってみてもらい、作業時間、情報の整理、連絡の混乱が変化したか確認します。役立たない場合は、機能を増やす前に原因を調べます。

## SEOとAdSenseに関する注意

検索流入だけを目的とする薄いページを増やさず、独自性があり読者の疑問を解決する内容を優先します。スマホでの読みやすさ、ナビゲーション、プライバシーに関する説明、正確な記述も重要です。アプリの開発を進めても広告審査への合格や収益は保証されません。審査上の問題があれば、別途原因を調べて改善する必要があります。

## 開発作業との関係

これは公開用の事業仮説であり、個人の毎日のToDoではありません。協力者は[開発タスク](BUILD_PLAN.ja.md)から興味のある作業を選び、実際の結果や分からなかった点を共有できます。個人の事業計画、非公開の参加者情報、個人の予定は公開しません。
